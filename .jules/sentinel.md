## 2026-03-08 - Nested Plaintext Password Logging in Booking Logs
**Vulnerability:** Plaintext temporal guest passwords were being logged to disk in `BookingController.php` log statements when initializing Paystack payments and handling the payment callbacks (which log full metadata arrays containing `guest_data.temp_password`).
**Learning:** Although generating temporary credentials for guests is highly convenient, storing those raw credentials in array payloads that are subsequently printed directly to application logs can lead to sensitive data exposure. Any system that logs payment objects, request data, or third-party callback metadata can inadvertently leak passwords.
**Prevention:** Implement recursive, key-based sanitization/masking functions (like `sanitizeForLog`) that scan nested array and object structures for standard sensitive keywords (e.g., `temp_password`, `password`, `secret`, `key`) and replace them with `[MASKED]` immediately prior to passing payloads to any logger.
